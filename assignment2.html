LSTM & Transformer Time-Series Forecasting

Browse assignment code →

1. Objective

Build a leakage-controlled pipeline for one-step-ahead prediction of Appliances energy use, using OpenCode to develop an LSTM. Examine variation across repeated sessions, audit generated suggestions, compare local language-model runs, and evaluate a Transformer under a shared forecasting protocol.

Reference LSTM: test MSE 7,452.4 Wh² on 200 held-out observations, compared with 8,743.0 for persistence. These are the audited assignment results.

2. Dataset

A2_data_release.csv contains 1,000 rows and 29 columns: a timestamp and 28 numeric variables. Observations run from 11 January 2016, 17:00 to 18 January 2016, 15:30 at regular 10-minute intervals, with no missing values or gaps.

  • Target: Appliances, energy use in Wh, with lag-1 autocorrelation approximately 0.77.
  • Available predictors include lighting, indoor temperature/humidity and outdoor weather.
  • rv1 and rv2 are exact duplicates; the reference model ultimately uses past Appliances values only.
  • Consumption is strongly right-skewed: median 60 Wh, mean 114.5 Wh and maximum 1,080 Wh.

3. Leakage-Controlled Methodology

The reference run (Session 3, seed 42) uses rows 0–639 for training, 640–799 for validation and 800–999 for testing. Raw observations remain chronological.

  • To predict row t, the model sees only rows [t − L, t).
  • Validation and test windows borrow immediately preceding history, producing a prediction for every target row without using future observations.
  • StandardScaler is fitted on training rows only. Metrics are calculated after inverse transformation to the original units.
  • Features, lookback and architecture are chosen using validation data. Test evaluation occurs once after freezing the choices.

4. Validation-Based Selection

Stage 1 compared univariate and six-variable inputs with lookbacks of 6, 12 and 24 steps, using a fixed 50-unit LSTM. Stage 2 compared 32 units, 50 units and a two-layer 50-unit model with dropout. The selected univariate, 24-step, one-layer model attained validation MSE 6,045.9 Wh².

The near-tie with a six-step lookback (6,189.0) should not be treated as evidence that 24 steps will always be better.

10. Generalized Prompt and Limitations

The final prompt uses Role, Input, Steps and Expectation. It generalises row counts, dates and lookbacks while keeping the experimental safeguards explicit.

Read the generalized forecasting prompt
Role: You are a data scientist building a robust LSTM pipeline for one-step-ahead Appliances prediction. Input: Use the provided CSV. Target is Appliances. To predict Appliances at time t, use only observations strictly before t; contemporaneous inputs at t are forbidden. Steps: 1. Inspect the data without assuming row count, date range, or statistics. Infer sampling interval from date differences; check missing values, gaps, exact duplicates, and redundant sensors. 2. Preserve chronological order. Split by proportion, e.g. roughly 60–70% train, 15–20% validation, 20% test; do not use fixed row numbers or dates and never shuffle observations. Within-window temporal order must always be preserved; shuffling whole training windows during optimisation is permitted. 3. Build past-only windows: input for row t is rows [t−L, t). Validation and test windows may borrow immediately preceding history (past-conditioning, not leakage). Produce one prediction per validation and per test row. 4. Apply StandardScaler (or justify an alternative) fitted on training rows only; apply the same transform to validation and test; inverse-transform before computing metrics. For the final refit, preprocessing may be refitted on train plus validation combined. Never fit preprocessing on test data. 5. Using training and validation only, compare a small set of input-feature subsets (include a univariate Appliances baseline; drop exact duplicates), a few short lookback candidates spanning roughly 1–4 hours of wall-clock time given the observed interval, and small LSTM capacities (at most two layers, tens of units, with dropout). Keep capacity appropriate for sample size. Justify selections briefly. 6. Select by validation MSE with early stopping on validation loss and best-weight restore. Do not use test data for any selection, tuning, or stopping. 7. Freeze all decisions, then evaluate once on the test period. Expectation: Report features, lookback in steps and wall-clock time, architecture, training hyperparameters (optimizer, learning rate, batch size, epochs/patience, seeds, batch order), and validation MSE. Plot test predicted versus actual over time; report test MSE/RMSE/MAE in original Appliances units with persistence (y(t−1)) and train-mean baselines. State assumptions and limitations.
  • One-step-ahead prediction uses observed history, not a recursive multi-step rollout.
  • Only one short time period is studied; stationarity and transfer to other periods remain uncertain.
  • Reusing validation for stopping and selection may introduce mild optimism.
  • Small validation sets, stochastic training and limited search budgets make nearby rankings uncertain.

Conclusion: the reference LSTM improves squared error over persistence, while the repeated runs and audits show why chronology, scaling, boundary history and validation-based selection must be checked explicitly.
